## 構成と実装されている機能

ViteとJavaScriptで構成された勤怠管理Webアプリです。Firebase Authentication、Realtime Database、Cloud Functions、FCMを使用しています。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面と起動入口。`/src/main.js`を読み込む |
| `src/main.js` | ログイン、社員管理、勤怠登録・編集・削除、カレンダー・集計、週次ルール、Excel出力、通知登録 |
| `src/firebase.js` | 環境変数からFirebaseクライアント設定を読み込む |
| `style.css` | 画面のスタイル |
| `functions/index.js` | 勤怠の作成・更新・削除をトリガーにした通知送信 |
| `public/firebase-messaging-sw.js` | バックグラウンド通知と通知クリック処理 |
| `public/service-worker.js` | Service Worker。変更時はキャッシュ動作も確認する |
| `database.rules.json` | 通常のFirebase設定から参照されるDBルール |
| `database.rules.dev.json` | 開発用のDBルール |
| `firebase.json` | Hosting（`dist`）、Functions、DBルールの設定 |
| `firebase.dev-test.json` | 開発用DBルールだけを指定した設定。HostingやFunctionsの設定は含まない |
| `vite.config.js` | ビルド先`dist`、公開ファイル元`public`の設定 |

ルートの`app.js`も存在しますが、現在のHTMLの起動入口は`src/main.js`です。変更対象を取り違えないでください。

主なDBパスは`employees`、`kintai`、`weeklyRules`、`usersByUid`、`admins`、`fcmTokens`です。権限はDBルールと、ユーザー・社員の対応関係を合わせて確認してください。開発用ルールにも特定UIDを参照する条件があるため、別のFirebaseプロジェクトでそのまま利用できるとは限りません。

## 自宅PCでの準備

1. この文書を含む変更を元のPCからコミット・プッシュした後、自宅PCで同じリポジトリ・作業ブランチをクローンまたはプルします。
2. Node.jsとnpmを用意します。Functionsの`package.json`はNode.js 22を指定しているため、まずNode.js 22系を利用する構成が候補です。実際のインストール済みバージョンは今回未確認です。
3. ルートディレクトリで依存関係をインストールします。

   ```powershell
   npm ci
   ```

4. `.env.development`を別途用意します。このPCには`.env.development`と`.env.production`がありますが、`.gitignore`の対象なのでGitからは復元できません。実値はこの文書に記載していません。
5. 開発用Firebaseの接続先を確認してから起動します。

   ```powershell
   npm run dev
   ```

6. 開発用ビルドを確認する場合は、次の順に実行します。

   ```powershell
   npm run build:dev
   npm run preview
   ```

7. Functionsを扱う場合だけ、`functions`ディレクトリでも`npm ci`を実行します。Firebase CLIと認証、対象プロジェクトの確認も別途必要です。

利用可能な本番ビルドコマンドは`npm run build:prod`です。開発・本番ビルドの出力先はいずれも`dist`なので、最後にどちらでビルドしたかを確認してください。

## 環境設定の項目（値は別途設定）

ソースコードが参照する項目:

```dotenv
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_DATABASE_URL=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_FIREBASE_VAPID_KEY=
VITE_FCM_ENABLED=false
```

`VITE_FCM_ENABLED`は文字列`true`の場合に通知処理を有効にする実装です。通知を試す場合は、開発側のFCM設定と対象端末を確認して変更してください。

`VITE_`で始まる値はフロントエンドへ組み込まれるため、サーバー用秘密鍵やパスワードを設定しないでください。上記Firebaseクライアント設定とサーバー用の秘密情報は別物です。

`.gitignore`では`.env`、`.env.*`、`node_modules`、`dist`、`.firebase`などを除外し、`.env.example`は例外として許可しています。現時点で`.env.example`はありません。秘密鍵ファイル全般が自動で除外される設定ではないため、新しい秘密ファイルを置く場合は先に除外対象を確認してください。
